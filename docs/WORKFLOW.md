# Workflow

이 문서는 AI와 함께 게임 개발 작업을 진행할 때의 사용자 개입 흐름과 문서 갱신 기준을 정의합니다.

## 핵심 원칙

- AI는 작업 시작 시 모든 문서를 자동으로 읽지 않습니다.
- 작업 요청은 먼저 `docs/PLAY_REQUEST.md` 형식으로 정리합니다.
- AI는 `docs/PLAY_REQUEST.md`에 적힌 작업 유형, 참조 문서, 수정 허용 범위를 우선 따릅니다.
- 참조 문서가 지정되지 않은 경우에만 `docs/AI_USAGE.md`의 최소 참조 규칙을 따릅니다.
- 추가 문서 확인이 필요하면, AI는 이유를 설명하고 사용자 확인을 받은 뒤 진행합니다.

## 작업 시작 흐름

1. 사용자는 새 작업이 생기면 `docs/PLAY_REQUEST.md`를 복사하거나 갱신해 작업 요청서를 작성합니다.
2. AI는 먼저 `docs/PLAY_REQUEST.md`만 확인합니다.
3. AI는 작업 유형과 수정 허용 범위를 파악합니다.
4. AI는 필요한 최소 문서만 추가로 확인합니다.
5. 요청서에 없는 문서 수정, 새 폴더 생성, 큰 구조 변경이 필요하면 사용자에게 먼저 확인합니다.
6. 작업이 끝나면 사용자가 허용한 문서만 갱신합니다.

## 사용자 개입 지점

아래 상황에서는 AI가 바로 진행하지 않고 사용자에게 확인합니다.

- 작업 유형이 불명확한 경우
- 참조할 문서가 지정되지 않았고 여러 문서가 관련될 가능성이 큰 경우
- 새 폴더, 새 시스템, 새 문서, 새 모듈이 필요한 경우
- 기존 기획과 구현 요청이 충돌하는 경우
- 게임 규칙, 밸런스, 승패 조건처럼 플레이 기준이 바뀌는 경우
- `docs/PLAY_REQUEST.md`에 적힌 수정 허용 범위를 넘어서는 경우

## 문서별 역할

- `docs/PLAY_REQUEST.md`: 사용자가 AI에게 전달하는 작업 요청서입니다.
- `docs/AI_USAGE.md`: AI가 문서를 적게 읽고 필요한 범위만 확인하기 위한 규칙입니다.
- `GDD/Game_GDD.md`: 게임 컨셉, 목표 경험, 핵심 기획을 정리합니다.
- `GDD/Implemention_Plan.md`: 기획을 실제 구현 순서와 마일스톤으로 나눕니다.
- `docs/PLANS.md`: 현재 작업 상태, 다음 작업, 보류 작업을 관리합니다.
- `docs/ARCHITECTURE.md`: 폴더, 코드, 에셋, 씬의 책임 범위를 정리합니다.
- `docs/GAME_RULES.md`: 플레이 판정, 점수, 승패, 턴, 밸런스 규칙을 기록합니다.
- `docs/Verify.md`: 구현 후 확인할 검증 항목과 완료 기준을 정리합니다.
- `docs/DECISIONS.md`: 반복해서 확인할 필요가 있는 확정 결정과 하루 작업 마무리 판단을 짧게 기록합니다.

## 작업 완료 후 갱신 기준

- 구현 계획이나 상태가 바뀌면 `docs/PLANS.md`를 갱신합니다.
- 확정된 기획 결정이 생기면 `GDD/Game_GDD.md` 또는 `docs/DECISIONS.md`를 갱신합니다.
- 구현 순서가 바뀌면 `GDD/Implemention_Plan.md`를 갱신합니다.
- 구조가 바뀌면 `docs/ARCHITECTURE.md`를 갱신합니다.
- 플레이 규칙이 바뀌면 `docs/GAME_RULES.md`를 갱신합니다.
- 검증 방법이나 완료 기준이 바뀌면 `docs/Verify.md`를 갱신합니다.
- 완료된 작업 이력은 커밋 기록을 기준으로 확인합니다.
- 하루 작업이 끝났거나 이후 작업에 영향을 주는 판단이 확정되면 `docs/DECISIONS.md`에 결정만 남깁니다.

## 충돌 처리

- 사용자 직접 요청이 가장 우선합니다.
- `docs/PLAY_REQUEST.md`와 다른 문서가 충돌하면 작업 전에 사용자에게 확인합니다.
- 구현 결과가 기존 문서와 달라졌다면 갱신 후보 문서를 먼저 제안합니다.
- 확실하지 않은 내용은 추정으로 확정하지 않고 `docs/PLANS.md`에 확인 필요 항목으로 남깁니다.
